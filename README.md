# Командная практика git: 1,5–2 часа

Это репозиторий вашей команды. Руководитель в работе не участвует: вы сами создаёте репозиторий, сами делаете review и сами сливаете pull request'ы.

Работаете всей командой в созвоне. Каждый в своём терминале, а один показывает экран. Это **ведущий**, он меняется на каждой миссии: читает задание вслух и следит, чтобы никто не застрял.

Порядок по кругу: **Участник 1 → Участник 2 → Участник 3 → Участник 1**. «Сосед» — следующий по кругу, он делает review вашего pull request.

## Правила на всю практику

1. Каждое изменение идёт через свою ветку и pull request. В `main` напрямую не пушим (кроме миссии 0).
2. Перед новой веткой всегда обновляем main:
   ```
   git checkout main
   git pull
   ```
3. Merge нажимает автор PR, и только после Approve соседа. GitHub не запретит слить без одобрения — это договорённость команды.
4. Застряли больше чем на 5 минут — пишите в чат группы, что делали и какую ошибку видите.

## Миссия 0. Создать репозиторий команды · 10 минут

**Делает Участник 1 (владелец), остальные смотрят его экран.**

1. На странице шаблона нажмите зелёную кнопку **Use this template → Create a new repository**.
2. Название: `praktika-a` (или `praktika-b`). Выберите **Private**. **Create repository**.
3. В новом репозитории: **Settings → Collaborators → Add people** → добавьте двух товарищей по команде и руководителя (`Vonagu3`, он только смотрит, как идут дела).
4. Товарищи принимают приглашение: письмо на почту или страница репозитория.
5. Владелец скачивает репозиторий (ссылка: зелёная кнопка «<> Code» → HTTPS):
   ```
   cd Desktop
   git clone https://github.com/ВАШ_ЛОГИН/praktika-a.git
   cd praktika-a
   ```
6. В VS Code откройте папку, нажмите **Ctrl+Shift+H** (на Mac **Cmd+Shift+H**) — замена во всех файлах. Замените `Участник 1` на имя первого, `Участник 2` на имя второго, `Участник 3` на имя третьего. Кнопка «Replace All» справа от поля.
7. Это единственный раз, когда пушим прямо в main:
   ```
   git add .
   git commit -m "Вписали имена команды"
   git push
   ```
8. Двое остальных скачивают репозиторий (`git clone` с той же ссылкой) и открывают папку в VS Code.

## Миссия 1. Визитка команды · 15 минут

**Ведущий:** Участник 1.

Каждый заполняет свой раздел в `визитка.md`: две строки под своим именем.

```
git checkout main
git pull
git checkout -b визитка-имя
```

Заполните свой раздел, сохраните, затем:

```
git add .
git commit -m "Визитка: имя"
git push -u origin визитка-имя
```

На GitHub откройте pull request («Compare & pull request»). Сосед: **Files changed → Submit review → Approve**. Автор: **Merge pull request**.

**На что посмотреть:** все трое правили один и тот же файл, а конфликта нет. Git соединяет изменения сам, если они в разных местах файла.

## Миссия 2. Неделя команды: конфликт у себя на компьютере · 30 минут

**Ведущий:** Участник 2.

В `неделя.csv` у каждого свой столбец. Впишите свои шаги (или другое число за день) **во все три строки**, в свой столбец. Например, если вы второй:

```
2026-10-05,,7100,
```

1. Все вместе:
   ```
   git checkout main
   git pull
   git checkout -b неделя-имя
   ```
2. Каждый вписывает свои числа, затем `git add .`, `git commit -m "Неделя: имя"`, `git push -u origin неделя-имя` и открывает PR.
3. Участник 1 сливает свой PR (после Approve соседа).
4. У остальных GitHub пишет «This branch has conflicts». **Решаем не в браузере, а у себя:**
   ```
   git pull origin main
   ```
   Git скажет `CONFLICT (content): Merge conflict in неделя.csv`.
5. Откройте файл в VS Code. В каждой строке два варианта: свой и тот, что уже в main. Соберите **одну** строку с числами обоих, например `2026-10-05,6400,7100,`. Удалите метки `<<<<<<<`, `=======`, `>>>>>>>`.

   Кнопки VS Code над конфликтом здесь не помогут: «Accept Current» и «Accept Incoming» оставят один вариант, и чужие числа пропадут, а «Accept Both» оставит две строки за одну дату. Собирайте строку руками.
6. Сохраните и закончите слияние:
   ```
   git add .
   git commit -m "Объединил неделю"
   git push
   ```
   Конфликт в PR исчезнет сам. Сосед делает review, автор сливает.
7. Следующий делает то же самое.

**Финал:** когда все трое слили PR, ведущий рисует график команды:

```
git checkout main
git pull
python 01_график.py неделя.csv
```

Картинку отправьте в чат группы. В git её не кладём.

## Миссия 3. Вопросы по git: просьба исправить · 25 минут

**Ведущий:** Участник 3.

Каждый пишет в `вопросы.md` один вопрос по git и правильный ответ. Ветка `вопросы-имя`, PR, как раньше.

**Новое: review с просьбой исправить.** Сосед внимательно читает вопрос и ответ.

- Всё верно и понятно: **Submit review → Approve**.
- Ответ неточный, вопрос непонятный, есть опечатка: комментарий у строки, затем **Submit review → Request changes**. Хотя бы один раз за миссию в команде должно быть Request changes.

Автор исправляет **в той же ветке**:

```
git add .
git commit -m "Поправил вопрос"
git push
```

Новый коммит сам появится в том же PR, новый PR не нужен. Сосед смотрит ещё раз → Approve → автор сливает.

## Миссия 4. От идеи к плану: issue закрывается сам · 25 минут

**Ведущий:** Участник 1.

1. Каждый заводит issue со своей идеей проекта: вкладка **Issues → New issue**. Можно взять ту, что писали на занятии. В описании: что сделать, для кого, какие данные нужны.
2. Поставьте 👍 идеям товарищей. Выберите идею, у которой больше всего 👍, и запомните её номер, например `#2`.
3. В `идея.md` у каждого свой раздел: «Задача», «Данные» или «Первый шаг» (имя указано в заголовке). 2–3 предложения. Ветка `идея-имя`, commit, push, PR, review, merge.
4. **Последний**, кто открывает PR, вписывает ещё и строку «Выбрана идея», а в описании PR пишет:
   ```
   Closes #2
   ```
   (свой номер). Когда этот PR сольют, issue закроется сам, и в нём появится ссылка на PR.

На следующем занятии команды выбирают тему проекта — этот файл и будет черновиком.

Вкладка **Pull requests → Closed**: 12 слитых PR, по 4 от каждого (визитка, неделя, вопросы, идея). Хотя бы в одном есть Request changes, а issue с выбранной идеей закрыт.

Ведущий последней миссии пишет в чат группы «Команда А закончила практику», прикладывает ссылку на репозиторий и картинку графика из миссии 2.
