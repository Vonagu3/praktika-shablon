# Практика git в паре: 1,5–2 часа

Это репозиторий вашей пары. Руководитель в работе не участвует: вы сами создаёте репозиторий, сами делаете review и сами сливаете pull request'ы.

Работаете вдвоём в созвоне. Каждый в своём терминале, а один показывает экран. Это **ведущий**, он меняется на каждой миссии: читает задание вслух и следит, чтобы никто не застрял.

**Участник 1** — владелец репозитория (кто это, сказано в чате группы), **Участник 2** — его напарник. Review вашего pull request делает напарник.

## Правила на всю практику

1. Каждое изменение идёт через свою ветку и pull request. В `main` напрямую не пушим (кроме миссии 0).
2. Перед новой веткой всегда обновляем main:
   ```
   git checkout main
   git pull
   ```
3. Merge нажимает автор PR, и только после Approve напарника. GitHub не запретит слить без одобрения — это ваша договорённость.
4. Застряли больше чем на 5 минут — пишите в чат группы, что делали и какую ошибку видите.

## Миссия 0. Создать репозиторий пары · 10 минут

**Делает Участник 1 (владелец), напарник смотрит его экран.**

1. На странице шаблона нажмите зелёную кнопку **Use this template → Create a new repository**.
2. Название: `praktika-1`, `praktika-2` или `praktika-3` (номер пары — в чате группы). Выберите **Private**. **Create repository**.
3. В новом репозитории: **Settings → Collaborators → Add people** → добавьте напарника и руководителя (`Vonagu3`, он только смотрит, как идут дела).
4. Напарник принимает приглашение: письмо на почту или страница репозитория.
5. Владелец скачивает репозиторий (ссылка: зелёная кнопка «<> Code» → HTTPS):
   ```
   cd Desktop
   git clone https://github.com/ВАШ_ЛОГИН/praktika-1.git
   cd praktika-1
   ```
6. В VS Code откройте папку, нажмите **Ctrl+Shift+H** (на Mac **Cmd+Shift+H**) — замена во всех файлах. Замените `Участник 1` на имя владельца, `Участник 2` на имя напарника. Кнопка «Replace All» справа от поля.
7. Это единственный раз, когда пушим прямо в main:
   ```
   git add .
   git commit -m "Вписали имена"
   git push
   ```
8. Напарник скачивает репозиторий (`git clone` с той же ссылкой) и открывает папку в VS Code.

## Миссия 1. Визитка пары · 15 минут

**Ведущий:** Участник 1.

Каждый заполняет свой раздел в `визитка.md`: две строки под своим именем.

```
git checkout main
git pull
git checkout -b визитка-имя
```

Заполните свой раздел, сохраните, затем:

```
git add .
git commit -m "Визитка: имя"
git push -u origin визитка-имя
```

На GitHub откройте pull request («Compare & pull request»). Напарник: **Files changed → Submit review → Approve**. Автор: **Merge pull request**.

**На что посмотреть:** вы оба правили один и тот же файл, а конфликта нет. Git соединяет изменения сам, если они в разных местах файла.

## Миссия 2. Неделя пары: конфликт у себя на компьютере · 40 минут

**Ведущий:** Участник 2.

В `неделя.csv` у каждого свой столбец. Миссия идёт в **два раунда**, чтобы конфликт решил каждый.

### Раунд 1: строки с 5 по 7 октября

1. Оба:
   ```
   git checkout main
   git pull
   git checkout -b неделя1-имя
   ```
2. Каждый вписывает свои шаги (или другое число за день) **в строки 05, 06 и 07**, в свой столбец. Например, если вы второй:
   ```
   2026-10-05,,7100
   ```
   Затем `git add .`, `git commit -m "Неделя 1: имя"`, `git push -u origin неделя1-имя` и PR.
3. **Участник 1** сливает свой PR первым (после Approve напарника).
4. У **Участника 2** GitHub пишет «This branch has conflicts». **Решаем не в браузере, а у себя:**
   ```
   git pull origin main
   ```
   Git скажет `CONFLICT (content): Merge conflict in неделя.csv`.
5. Откройте файл в VS Code. В каждой строке два варианта: свой и тот, что уже в main. Соберите **одну** строку с числами обоих, например `2026-10-05,6400,7100`. Удалите метки `<<<<<<<`, `=======`, `>>>>>>>`.

   Кнопки VS Code над конфликтом здесь не помогут: «Accept Current» и «Accept Incoming» оставят один вариант, и чужие числа пропадут, а «Accept Both» оставит две строки за одну дату. Собирайте строку руками.
6. Сохраните и закончите слияние:
   ```
   git add .
   git commit -m "Объединил неделю"
   git push
   ```
   Конфликт в PR исчезнет сам. Участник 1 делает review, Участник 2 сливает.

### Раунд 2: строки с 8 по 10 октября

То же самое, ветки `неделя2-имя`, строки 08, 09 и 10. Но теперь **первым сливает Участник 2**, а конфликт у себя решает **Участник 1**.

**Финал:** когда все четыре PR слиты, ведущий рисует график пары:

```
git checkout main
git pull
python 01_график.py неделя.csv
```

Картинку отправьте в чат группы. В git её не кладём.

## Миссия 3. Вопросы по git: просьба исправить · 25 минут

**Ведущий:** Участник 1.

Каждый пишет в `вопросы.md` один вопрос по git и правильный ответ. Ветка `вопросы-имя`, PR, как раньше.

**Новое: review с просьбой исправить.** Напарник внимательно читает вопрос и ответ.

- Всё верно и понятно: **Submit review → Approve**.
- Ответ неточный, вопрос непонятный, есть опечатка: комментарий у строки, затем **Submit review → Request changes**. Хотя бы один раз за миссию в паре должно быть Request changes.

Автор исправляет **в той же ветке**:

```
git add .
git commit -m "Поправил вопрос"
git push
```

Новый коммит сам появится в том же PR, новый PR не нужен. Напарник смотрит ещё раз → Approve → автор сливает.

## Миссия 4. От идеи к плану: issue закрывается сам · 25 минут

**Ведущий:** Участник 2.

1. Каждый заводит issue со своей идеей проекта: вкладка **Issues → New issue**. В описании: что сделать, для кого, какие данные нужны.
2. Обсудите обе идеи и выберите одну. Поставьте ей 👍 и запомните её номер, например `#2`.
3. В `идея.md` у каждого свой раздел (имя указано в заголовке). 2–3 предложения. Ветка `идея-имя`, commit, push, PR, review, merge.
4. **Второй**, кто открывает PR, вписывает ещё и строку «Выбрана идея», а в описании PR пишет:
   ```
   Closes #2
   ```
   (свой номер). Когда этот PR сольют, issue закроется сам, и в нём появится ссылка на PR.

На следующем занятии выбираем темы проектов — этот файл будет одним из черновиков.

## Как понять, что всё сделано

Вкладка **Pull requests → Closed**: 10 слитых PR, по 5 от каждого (визитка, неделя 1, неделя 2, вопросы, идея). Хотя бы в одном есть Request changes, а issue с выбранной идеей закрыт.

Ведущий последней миссии пишет в чат группы «Пара 1 закончила практику» (свой номер), прикладывает ссылку на репозиторий и картинку графика из миссии 2.
